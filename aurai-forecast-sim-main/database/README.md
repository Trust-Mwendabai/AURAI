# Database

The MySQL/MariaDB schema the PHP API in [`/api`](../api/README.md) runs against. See [`/docs/DATA-MODEL.md`](../docs/DATA-MODEL.md) for the entity reference and [`/docs/PHP-MIGRATION.md`](../docs/PHP-MIGRATION.md) for why the schema is shaped the way it is.

Apply it once and the app is ready to use — see [the project README](../../README.md) for full setup.

## Files

- **`schema.sql`** — the entire schema in one file, in dependency order. Fastest way to stand up a fresh database (e.g. paste into phpMyAdmin's SQL tab, or pipe into the `mysql` CLI).
- **`migrations/`** — the same schema split into ordered, single-purpose files (one table per file, run in filename order). Use these if you want incremental migrations tracked one-by-one (e.g. with Phinx, Laravel migrations, or a custom runner), or if you're applying this to a database that already has some of these tables.

Requires MySQL 8.0.13+ or MariaDB 10.2.1+ (for JSON columns with expression defaults). Any current XAMPP install satisfies this. If you're stuck on an older server, see the compatibility note at the top of `schema.sql`.

## Applying the schema

**Option A — one shot, via the `mysql` CLI** (XAMPP's bundled MySQL/MariaDB):

```sh
"C:\xampp\mysql\bin\mysql.exe" -u root -p < database/schema.sql
```

**Option B — phpMyAdmin**: open phpMyAdmin, use the "Import" tab (or the "SQL" tab and paste the file contents) against a new or existing connection — `schema.sql` creates the `aurai_forecast` database itself via `CREATE DATABASE IF NOT EXISTS`.

**Option C — migrations, one at a time**, in order:

```sh
for f in database/migrations/*.sql; do
  "C:\xampp\mysql\bin\mysql.exe" -u root -p aurai_forecast < "$f"
done
```

(On Windows PowerShell, loop with `Get-ChildItem database/migrations/*.sql | Sort-Object Name | ForEach-Object { & "C:\xampp\mysql\bin\mysql.exe" -u root -p aurai_forecast < $_.FullName }` — note PowerShell doesn't support `<` redirection into a native exe directly, so prefer `Get-Content $_.FullName | & "C:\xampp\mysql\bin\mysql.exe" -u root -p aurai_forecast` or just run the loop from Git Bash instead.)

## Things worth knowing

- **Access control lives in PHP, not the database.** MySQL has no row-level security, so every query in `/api` filters by the authenticated `user_id` itself. Miss that filter and a query returns other people's rows — see [`/docs/AUTHENTICATION.md`](../docs/AUTHENTICATION.md).
- **UUID primary keys are generated by the application**, not the database (`uuid4()` in `api/lib/helpers.php`). MySQL can't portably default a column to a UUID.
- **`updated_at` columns use native `ON UPDATE CURRENT_TIMESTAMP`** — no triggers needed.
- **One trigger exists**: `users_after_insert` creates the matching `profiles` and `user_settings` rows on registration, so the API can't forget to.
- **`messages.seq`** is an AUTO_INCREMENT ordering column. `created_at` is only second-precision, so a question and an instant answer share a timestamp and can't be ordered by it.
